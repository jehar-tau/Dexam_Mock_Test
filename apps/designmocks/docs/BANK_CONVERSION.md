## Structured correction queue

`bank:diagnostics` is a read-only operator command. It verifies local canonical PNG bytes before running the same evaluator used by the runtime materializer. It emits aggregate counts only; an optional private JSON report contains stable keys, exact source hashes, diagnostic codes/locations, corrective actions and scope classification. It contains no prompts, options, answer keys or runtime payloads. A report records source, rule, media, runtime-plan and report digests so a later correction cannot silently reuse an older result.

```bash
mkdir -p private-import
npm run bank:diagnostics -- --ref origin/main --media-root "$DMOCKS_MEDIA_ROOT" --output private-import/conversion-queue.private.json
```

Set `DMOCKS_MEDIA_ROOT` to the owner's read-only canonical image folder. Output creation is exclusive with private permissions: existing reports, tracked/unignored repository paths, public/source/build directories, Git internals and public-directory symlinks are rejected. Choose a new private filename for a later run. The command has no apply/approval/provider-write option and never infers an answer or a numerical tolerance.

### Private authored practice editor

The admin desk offers **NID practice blueprints** under the owner's bank-usability exception. New drafts have no preset count, duration, marks or rubric. An administrator explicitly chooses the practice purpose, clock, response sections, counts and per-question marks/penalties. Drawing/written-page sections require a human rubric whose criteria sum exactly to the maximum, zero wrong-answer penalty and an explicit ten- or fifteen-minute completed-page upload period. Objective-only practice has no upload grace. The editor supports single-choice, exact-set, numeric and uploaded-response design records; it does not claim those schemes are official NID formats or already supported runtime contexts.

Every save creates an immutable content revision and server digest, with a new pending practice review. A decision requires the current revision/digest and a human review note; editing a reviewed/rejected version preserves that older content/decision and creates a fresh draft. Historical versions are read-only. Database compare-and-swap locks prevent competing saves or reviews from overwriting one base version. Actor-bound request IDs make an explicit retry safe; a lost/incomplete reply locks further edits until the admin checks its saved acknowledgement or retries that identical command. There is no automatic write replay or browser persistence of private drafts.

Four staff-only RPC signatures are added to the exact MVP allowlist. Anonymous users, students, drawing reviewers and service-role table access are denied. Each browser dispatch uses the existing freshly verified, pinned administrator/account scope, a bounded deadline and stale-read suppression. Role loss, sign-out, account replacement and navigation clear the editor. No existing exam blueprint, source payload/hold, runtime conversion, approval, answer key, paper, attempt, entitlement, admission or sales state is changed by this workflow. In particular, reviewing a practice blueprint does not make any of the 637 NID records ready for delivery.

Binding is separate from conversion and question approval. Actor-bound request IDs and compare-and-swap source/context checks prevent duplicate or stale binding writes. Lost/incomplete replies lock further actions until saved-state inspection or an explicit identical retry. Role/account loss clears source and context previews. Blueprint pagination remains bounded and unreviewed/incompatible choices are disabled. The current bound scheme/rubric remains visible during final question review.
