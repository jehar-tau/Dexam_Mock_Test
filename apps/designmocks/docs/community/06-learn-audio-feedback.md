# 6. Track L: audio feedback in Learn

A separate track from Community. It touches only `src/learn/`, follows the
Learn build kit in `docs/learn/`, and ships under Learn's own release
switch. It is recorded here because it arrived with the Community brief;
when work starts, move this file's content into `docs/learn/` as a
foundation work package.

## The idea

When a student answers a Learn question wrongly, the explanation of what
went wrong and how to approach the question is also spoken aloud. A switch
turns audio off.

## What exists

Every Learn check already produces written, reasoned feedback for the
chosen wrong option, generated by the topic engine together with the
question. So the words to speak already exist for every generated
question; no new content has to be authored.

## Two ways to make the sound

| | Device voice | Recorded or generated audio files |
|---|---|---|
| How | The browser's built-in speech synthesis reads the feedback text | Audio files produced ahead of time and stored |
| Cost | None | Per character or per recording, plus storage |
| Works with generated questions | Yes, any text | Only for fixed text; generated questions have endless variants |
| Quality | Depends on the phone; fine on recent Android and iOS, uneven on old devices | Consistent |
| New dependency | None | A speech provider, or studio time |

**Recommendation:** device voice first. Learn's questions are generated,
so pre-recorded audio cannot cover them without a paid speech service
called at run time, which is a cost and a provider decision for the owner
(open decision 10).

## Behaviour

- Speaks only after a wrong answer, and only the feedback already on
  screen. The written feedback always stays visible; audio is an addition,
  never the only channel.
- A speaker switch in the lesson player header, remembered on the device.
  Off by default until the student turns it on once (browsers also require
  a tap before any sound).
- Stops at once when the student moves to the next screen, switches the
  tab or turns the switch off.
- Text is prepared for speech: symbols and notation in the feedback are
  spelled out ("90 degrees", "face A").
- Prefers an Indian English voice when the device has one; falls back to
  the default English voice; hides the switch when the device has none.
- No recording, no microphone, nothing sent to a server.

## Work packages

1. `src/learn/speech.mjs`: pure text preparation and voice choice, unit
   tested.
2. Player integration: the switch, speak on wrong answer, stop on
   navigation.
3. Browser journeys on desktop and Pixel 7 with speech synthesis stubbed;
   accessibility check that the switch is labelled and the feedback is
   still announced to screen readers without double-speaking.
4. Try it on real low-cost Android phones before deciding it is good
   enough.
